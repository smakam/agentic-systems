# Chapter 14 — Instructor demo walkthrough

Approved sequence: five saved semantic answers judged by Claude in our script, followed by three saved structured answers graded natively by Langfuse. The learner activities reuse supplied outputs and make no model calls.

## Preparation

Run commands from the application repository root. Start the existing local lab; the UI is `http://localhost:3000`, project `marketplace-support`. The portable files are in `course/exercises/chapter-14-evaluation/`. Command outputs persist under `app/results/chapter-14/` through the existing `/results` mount.

Keep the two axes separate: offline versus production describes the data/lifecycle; script versus native describes where grading executes. Candidate answers are reused here. Gold/reference data goes to evaluators, not candidate model context. Do not reset the interactive marketplace or call the candidate agent during these activities.

## Before the demo: what the Langfuse sections mean

| Section | Purpose | In this demo |
| --- | --- | --- |
| Datasets | Questions, expected answers and metadata | Five Claude cases or three structured cases |
| Experiments | A named dataset run with actual outputs and scores | External-Claude run or native structured run |
| Evaluators | Automated grading definitions and execution rules | TypeScript checks of status and quantity |
| Human Annotation | Reviewers assign scores and comments inside Langfuse | Available capability; our learner activity imports human grades made outside it |
| Scores | Stored grading outcomes, reasons and provenance | API for imported grades; EVAL for native automated grading |

The OUTPUT is the candidate model's answer. In Part A it is Nano's saved answer, not an answer generated by Claude. Claude produces the grade and rationale. Dataset references alone do not tell you where grading happened. In an experiment, select **Show details** to inspect its description; the script-import run says that grading occurred externally. Score source API identifies external submission, while source EVAL identifies the native evaluator. API alone does not prove which external grading method was used; combine it with this run's description and saved script results.

## Production evaluation discussion

The production diagram remains proposed: **all thumbs-down runs** receive targeted review/evaluation; **only positive/unrated runs** are sampled. Inspect answer/evidence/trace and distinguish agent error, mistaken feedback and ambiguous criteria. After inspecting the answer/evidence/trace, a reviewer approves independently supported reference answers and criteria. A useful golden test case may be retained whether the outcome is an agent error or mistaken feedback/ambiguous criteria; confirmed agent errors require fixing the agent and rerunning regression evaluation. A confirmed evaluator error requires fixing its rubric/instructions/reference and re-evaluating the correct saved answer against validated gold, so the wrong judgment does not recur. Feedback itself never becomes gold automatically. Feedback exists; the automatic production selector/pipeline does not.
