# Chapter 14 — Instructor demo walkthrough

## Workspace for this activity

Use [local Langfuse](http://localhost:3000), project **marketplace-support**, and the supplied answer fixtures. No marketplace UI or business database is required for this activity. Run the documented import commands from the application repository root; keep the configured Langfuse worker and dispatcher running.

This is a walkthrough of recorded results. Do not run scripts or make model calls during the demonstration. The scripts remain available separately for preparation and learner uploads.

## Langfuse navigation

| Section | What to show |
| --- | --- |
| Datasets | Test questions, golden references and metadata |
| Experiments | Recorded model answers and their evaluation scores |
| Evaluators | Automated grading code and the rule selecting answers to score |
| Human Annotation | Human review inside Langfuse; available, but not used in this demo |
| Scores | User feedback, human grades and automated grades; each row is one score |

A dataset is not a set of model answers by itself. Its expected output is the golden reference. The experiment's OUTPUT is the candidate answer; the evaluator produces scores and reasons.

### 2. Show the recorded experiment and model identities

Open [chapter14-nano-claude-model-details](http://localhost:3000/project/marketplace-support/experiments/results?baseline=617004fb6c879e31).

Confirm five items. Select **Show details**. The description identifies **GPT-5 nano** as the answer model and **Claude Opus 5.5** as the configured judge model. Open **Metadata** for the precise model versions, judge identity basis, grading method and rubric.

The saved judge response records the gateway alias; the Claude provider name is the configured LiteLLM route, labelled accordingly. Our script ran Claude outside Langfuse and imported its grades. No new answers or judgments were generated by this model-labelled import. The historical runs remain separate.

### 3. Compare question, gold, candidate answer and Claude judgment

Read one row across: **Input → Expected Output → OUTPUT → claude_correctness**. OUTPUT is Nano's saved answer, not an answer generated by Claude.

Use three examples:

| Question | Score | Meaning |
| --- | ---: | --- |

| Has the payment gone through for order-1? | 1 | Partial: buyer payment is described, but seller payout is not distinguished |
| Did the payout incident affect every seller? | 0 | Incorrect: the answer asks an unrelated clarification and misses incident scope |

Open a result row and inspect the score comment/reason. Compare that explanation with the golden requirements. The full five scores are **2, 1, 1, 1, 0**. The displayed average **1.00** is an average on the 0–2 scale, not a percentage or a count of correct answers.

### 4. Explain where grading happened

The experiment description says grading occurred externally. The score source is **API**: our script submitted it. Source API alone does not identify the grader; the experiment metadata and saved judge results establish Claude's role.

The imported task's zero cost describes replay/publication, not the original answer generation or Claude judging. The original five judge calls had a gateway cost estimate of USD 0.192392. No live call is needed for this demonstration.

### 2. Show the native TypeScript evaluator

Open [Chapter14 structured order comparison](http://localhost:3000/project/marketplace-support/evals/v2/cbbcc51f-decd-4305-a46b-a9d38d5cd390).

Point out the TypeScript comparison and its checks: valid schema, matching shipment status and matching quantity. Show the rule selecting observations named `chapter14-structured-answer` at 100% sampling. Langfuse's worker executes this code; there is **no LLM judge model**.

Both fields match → correct. Correct status but wrong quantity → partial. Wrong status → incorrect. Invalid schema and missing reference have separate outcomes. This narrow evaluator does not check semantic explanations or whether citations support claims.
