# Chapter 14 — Instructor demo walkthrough

## Workspace for this activity

Use [local Langfuse](http://localhost:3000), project **marketplace-support**, and the supplied saved answers. No marketplace UI or business database is required for this activity. Run the documented import commands from the application repository root; keep the configured Langfuse worker and dispatcher running.

Start with recorded results, then run one native code-evaluator sample test in the UI. Do not run scripts or make model calls during the demonstration. The scripts remain available separately for preparation and learner uploads.

## Langfuse navigation

| Section | What to show |
| --- | --- |
| Datasets | Test questions, golden references and metadata |
| Experiments | Recorded model answers and their evaluation scores |
| Evaluators | Automated grading code and the rule selecting answers to score |
| Human Annotation | Human review inside Langfuse; available, but not used in this demo |
| Scores | User feedback, human grades and automated grades; each row is one score |

A dataset is not a set of model answers by itself. Its expected output is the golden reference. The experiment's OUTPUT is the candidate answer; the evaluator produces scores and reasons.

## Part D — Run one evaluator test inside Langfuse

Before recording, enable the dispatcher on **both** web and worker using the [setup instructions](README.md#learner-setup--complete-once-before-the-exercise). Retain other local Compose overlays. The single-sample test was successfully rehearsed on 21 October 2026 after restoring these settings; saved historical scores alone do not prove the dispatcher is enabled now.

1. Open **Evaluators → Chapter14 structured order comparison**. There is no separate “Evaluator Tests” tab in the rehearsed UI.
2. On the right, find **Test with sample observations**. Keep the filter for observations named `chapter14-structured-answer`. The selected sample contains the original question, saved JSON answer and stored independent expected values.
3. Select the radio button for a supplied real answer, such as item-1/order-1 with `delivered` and quantity `2`. Avoid deliberately authored calibration controls for this first demonstration.
4. Click **Run test on this sample**. Read the result: `structured_grade` correct and all three field checks true. This reruns code grading; it does not call an agent, produce a new model answer or create a new experiment.
5. If **code eval dispatcher is not configured** appears, reapply the setup overlay to both services and refresh. Do not edit evaluator code to work around a runtime configuration error.

For a new experiment, the supplied importer reads the JSON answers, creates a named dataset run and links each answer to its dataset item. The enabled observation rule triggers asynchronous native scoring. Do not present the UI **Run experiment** button as the entry point for our supplied-answer workflow. A live application runner would generate new answers instead; this chapter's learner run reuses provided ones.

Show [exercise.md](https://github.com/smakam/agentic-systems/blob/main/course/exercises/evaluation/exercise.md).
